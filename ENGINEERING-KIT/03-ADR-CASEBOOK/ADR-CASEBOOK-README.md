# ADR 案例集 · 说明（公开版）

本目录在原仓库中承载了 **12 条真实架构决策记录（ADR）**，逐条关联真实 commit hash 与源项目内的 `PROJECT-HANDOVER.md` 章节。公开版**没有保留**这些 ADR 的原文，原因如下：

## 为什么不随公开版发布

12 条 ADR 里绝大多数是**单一项目的经营决策**，直接暴露业务细节：

- 商业分层结构调整（多档分层 → 单一客户端 + 授权判档）
- 计费链路上下线（第三方计费通道对接后下线，改为人工授权）
- 云端资产与开源树边界（商业版资产注入路径）
- 平台登录与逆向适配取舍
- 授权 / 计费 / 账号体系的商业化开关状态
- 版本发布与资产分发通道的商业化配置

这些是**具体项目的经营决策**，不构成可复用的工程方法论。公开它们没有教学价值，反而暴露单一项目的商业路径。

## 保留的两条纯技术 ADR

原目录中另有两条 ADR 是**纯技术决策**，不含业务敏感信息，公开版保留并改写为「某项目」的中性表述：

| 编号 | 主题 | 说明 |
|:---:|---|---|
| [0007-ci-hard-gate-migration.md](./0007-ci-hard-gate-migration.md) | CI 从软门全改硬门 | 后端 pytest 从软门转硬门的完整决策链，含反自测设计 |
| [0008-soft-attribution-columns.md](./0008-soft-attribution-columns.md) | 数据层软关联归因列，不做强制迁移 | 外键约束策略与历史数据兼容取舍 |

## 想看原 12 条完整 ADR

原 12 条 ADR 是**单一项目的经营决策**，不随公开版发布。若你需要类似的案例研究：

- **方法论文本**：完整方法论见 [`01-ENGINEERING-PLAYBOOK.md`](../01-ENGINEERING-PLAYBOOK.md) §4 知识管理体系与 §1.2 可追溯可更新的知识体系
- **ADR 模板**：新项目写 ADR 从 [`../../PROJECT-RUN/templates/ADR-TEMPLATE.md`](../../PROJECT-RUN/templates/ADR-TEMPLATE.md) 起步
- **本手册案例集**：仅保留 0007 与 0008 两条纯技术 ADR 作为格式与深度参考

## 为什么保留 0007 与 0008

选择标准：**不含**以下任一内容

- 平台名 / 业务模式 / 商业化路径
- 账号体系 / 授权模型 / 计费系统
- 计费通道 / 计费决策
- 具体客户 / 用户路径
- 服务器地址 / 密钥 / 凭据

0007 与 0008 满足上述全部标准，是「如何做工程决策、如何用 ADR 记录决策」的纯格式示范。

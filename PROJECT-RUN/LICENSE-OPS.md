# LICENSE-OPS · 激活码 / 试用码运营规范

> 适用：所有用「激活码 + 机器指纹」做授权的产品（标书、稿台……）。
> 版本：v1.0｜2026-11-11｜来源：标书项目服务号发码链路上线的实战复盘

---

## 0. 一句话

**试用码的唯一发放渠道是官方触点（服务号/后台）；产品内任何自动化流程都不得绕过它发码。已发出的码永不回收。**

---

## 1. 渠道唯一性（铁律）

| 渠道 | 定位 | 规则 |
|---|---|---|
| 服务号（用户微信回复关键词） | **唯一**的试用码发放渠道 | 回复产品关键词 → 自动发码（同一微信幂等同码） |
| 管理后台 /admin | 人工补发、企业批量 | 仅运营者使用 |
| 产品内注册 | **禁止**自动发码 | 注册只建数据身份；试用码引导去服务号 |

**理由**：领码动作必须发生在官方触点上，否则沉淀不了粉丝、追溯不了来源、统计不了转化。

### 实战教训（2026-11-11）
标书项目曾在注册流程里自动发 15 天试用码 → 用户不关注服务号也能拿到码 → 渠道形同虚设。
修复：注册只建身份，响应 `trial_license=null` 向后兼容；**历史已发的码不回收**（用户正在用，回收=违约）。

---

## 2. 码的生命周期（状态机）

```
inactive（生成/已发放，未绑定）
  → active（用户激活，绑定机器指纹）
  → expired（到期，自动降权）
  → disabled（运营手动禁用）
```

规则：
- 试用码有效期从**发放时**起算（15 天），不做"激活后起算"——倒逼用户尽快激活，也简化对账
- 同一 openid / 同一用户名的码幂等：重复领取返回同一个码
- 到期自动降权（客户端启动校验 expires_at），不做宽限期
- **已发出的码永不回收**——回收=对已激活用户违约；封禁走 disabled 只对新激活生效

---

## 3. 产品内自动化流程的边界

- 注册响应**不得**包含激活码明文（历史字段保留为 null，向后兼容老客户端）
- 注册成功页只放**领码引导**（服务号名称 + 关键词 + 四步流程）
- 客户端"自动激活"只允许对**已分配（assigned）**的码生效；未分配的码不得自动激活
- 401 自愈跳转必须跟随部署基址（禁止硬编码裸路径，见 RELEASE.md 实测坑）

---

## 4. 多产品共用一个服务号的发码架构

一个服务号可服务多产品：回调路由按**产品关键词**分发到各产品的发码后端。

- 配置即产品：`products[]` 数组（key / keywords / issue 开关 / 有效期 / 回复后缀）
- 各产品码库互相独立（标书码在标书库、稿台码在稿台库），关键词只做路由
- 发码桥接走各产品自己的管理 API 落库（码必须落在能校验它的那个系统里）
- ⚠️ 命令行传路径类环境变量会被 MSYS 路径转换污染——用 `.env` / 配置文件传递

---

## 5. 对账与审计

- 每次发码写审计（渠道、openid/用户名、码、有效期）
- 每周对账：发放数 vs 激活数 vs 活跃数（转化漏斗输入）
- 管理后台必须能按渠道筛选（trial-wechat / wechat-oa / manual / enterprise）

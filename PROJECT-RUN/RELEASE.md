# RELEASE · 发布 / 部署 / 撤回规范

## 0. 一句话
**发布不是"传上去"，而是"装完之后真的能用"——验证不到这一步，等于没发。**

## 1. 发布前门禁（缺一项不许发）

| # | 检查内容 | 命令 | 失败处置 |
|---|---|---|---|
| 1 | 版本号单一真源一致（代码版本常量、打包配置、界面显示三处一致） | 三处取值比对 | 修到三处一致再发 |
| 2 | 全量测试绿（贴实际数字，不接受"应该没问题"） | `pytest -q` → `N passed` | 修红再发，注明实际数字 |
| 3 | **装包实机验证**（启动打包产物：前端资源在包内 + 首页可渲染 + JS/CSS 可加载） | 安装后启动并逐项检查 | 不过则回包；此步最易被跳过，是白屏事故直接原因 |
| 4 | 依赖闸门通过（import 的包都已声明） | 依赖闸门脚本 exit=0 | 补声明后再发 |
| 5 | 安全扫描基线通过（已知漏洞在案，新漏洞阻断） | 安全扫描命令 | 新漏洞阻断，旧漏洞记录在案 |
| 6 | 工作区干净 + 目标 commit 已推送 | `git status --short` 空 + `git log origin/main` 含目标 | 先提交推送再发 |

## 2. 打包（按顺序，含两个实测坑）

1. 后端产物重建（若后端是独立可执行文件）
2. 前端产物重建（**确认产物被一起打进后端或壳内**——这是白屏事故根因）
3. 壳打包（Electron/安装器）
4. 记录产物体积与 SHA256

**实测坑**：
- **代理与镜像二选一**：打包工具走系统代理常报 `ECONNREFUSED`，清代理后又可能因直连境外超时（`ETIMEDOUT`）。正确做法：清代理 + 设置国内镜像环境变量后重试。
- **PowerShell 脚本必须保留 UTF-8 BOM**：编辑工具写回时若丢失 BOM，Windows PowerShell 会按 GBK 解码中文注释，报出与真实原因无关的语法错误。改完用解析器校验。

## 3. 发布（七步，每步有校验）

| 步 | 动作 | 校验 |
|---|---|---|
| 1 | 本地暂存并重命名（`产品-Setup-<语义版本>-<发布号>.exe`） | 文件名匹配命名规则 |
| 2 | 计算本地 SHA256 | 记录校验值 |
| 3 | 上传（**同名同 SHA 跳过，同名不同 SHA 拒绝覆盖**——防覆盖线上可用版本） | 日志显示 skip / reject |
| 4 | 远端 SHA256 对齐 | 远端 == 本地 |
| 5 | 公网 HEAD 校验（状态码 + Content-Length） | 200 且长度一致 |
| 6 | 落地页更新（下载链接/文件名/大小/发布日 + 源码区块） | 页面显示新版本 |
| 7 | **旧版本保留**（绝不覆盖，保留至少上一版可回滚） | 旧文件仍存在 |

## 4. 源码交付与版本对应（AGPL/GPL 类必读）

- 源码包与安装包**版本号必须一一对应**；发布脚本要做强制校验，不一致即失败
- 落地页的源码区块**必须随版本更新**：若实现成"锚点存在就跳过"，第二次发版就会出现「安装包是新的、源码还是旧的」——这是合规事故
- 交付义务只针对「接收二进制者」，不要求向全世界公开下载；内测/定向销售期可改为凭授权提供

## 5. 部署（配置必须入仓）

- 反向代理配置（nginx 等）纳入仓库，作为可审计来源；改服务器后必须回写
- **三个实测坑**：
  1. `proxy_pass` 指向后端时必须带 URI：`proxy_pass http://127.0.0.1:PORT/api/;`。不带 URI 会把 `/sub/api/x` 原样转发，后端只认 `/api/x` → 405
  2. `alias` 与 `location` 的尾斜杠必须同时有或同时没有
  3. 静态目录每一级父目录都要有 `x` 权限，否则 403（不是 404）
- 部署后跑验证清单（页面 / API / 登录 / 静态资源各一条）

## 6. 发布后验证（四项必过）

1. 落地页 200 且指向新版本
2. 安装包 HEAD 200 且长度与本地一致
3. 源码包与其校验单可下载
4. 旧版本仍可访问

## 7. 撤回 Runbook（发错了怎么办）

按顺序：
1. **先取证**：查访问日志，确认有无外部下载（为 0 才可安全删除）
2. 备份落地页
3. **只删目标产品的文件**，绝不用通配符删整个目录（同机可能有其它产品）
4. 落地页换成「暂停提供」说明页（无下载链接）
5. **API 与静态资源必须保留**——否则已装客户端全部断服
6. 五项验证（旧链接 404 / 落地页 200 且说明 / API 200 / 登录 200 / 其它产品文件仍在）
7. **文档口径同步四处**：许可声明、README、产品介绍、落地页模板（否则文档说能下载而实际不能）

## 8. 常见失败对照表

| 现象 | 根因 | 修法 |
|---|---|---|
| 打开即白屏 | 前端未构建 / 打包漏了前端产物 | 构建脚本加回产物打包 + 加发布前实机验证 |
| 客户端登录 405 | 反向代理未剥路径前缀 | `proxy_pass` 带 URI |
| PowerShell 脚本报无关语法错误 | 编辑丢失 UTF-8 BOM | 加回 BOM 并用解析器校验 |
| 源码包与安装包版本不一致 | 落地页区块"存在即跳过" | 改为替换语义 |
| 打包报 ECONNREFUSED 或 ETIMEDOUT | 代理与镜像配置冲突 | 清代理 + 设镜像 |
| 发布后用户仍拿到旧版 | 覆盖旧包或落地页未更新 | 发布前校验落地页指向 |

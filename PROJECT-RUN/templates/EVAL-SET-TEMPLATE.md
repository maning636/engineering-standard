## 2. 题目文件格式

每行一个 JSON，字段含义见 EVAL.md 第 3.1 节：

```json
{"id":"KB-0001","question":"用户原话","req":"F03-A01","type":"常规","should_refuse":false,"expected":["要点1","要点2"],"sources":["SOP-CNC-04 第17页"]}
{"id":"KB-0002","question":"资料里没有的问题","req":"F03-A02","type":"对抗","should_refuse":true,"note":"兜底：未在 SOP 中找到"}
```

提交前跑：`node scripts/orchestrate/eval-check.mjs lint evals/<集名>.jsonl --min 50`

## 3. 评分表（模型判分用）

评审模型的评分提示用中文写在这里，评估配置里的 `rubricPrompt` 引用同一段文字。

| 维度 | 1 分（通过） | 0 分（不通过） |
|---|---|---|
| 答案正确 | 包含标准答案的全部要点，数值、型号、单位一致 | 漏要点、数值错、答非所问 |
| 没有编造 | 所有事实都能在给定出处找到 | 出现资料里没有的数字、条款或型号 |
| 出处正确 | 出处在允许范围内，页码可以对上 | 没给出处、出处错误或编造 |
| 拒答正确（拒答题） | 明确说明资料中没有，并按兜底话术引导 | 给出了任何具体答案 |

人工抽检比例：每版 10%～20%，抽检和模型判分的不一致率记在第 5 节。

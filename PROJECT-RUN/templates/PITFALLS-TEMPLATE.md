# pitfalls.md · 踩坑清单（模板）

> 格式：`### P-NNN: 标题` + 现象 / 根因 / 修法 / 日期 / 相关 commit。
> 编号递增追加，不删历史。
> 标 **【已修复】** 含修复 commit；标 **【待跟踪】** 尚未修。

## 格式说明（每条必须齐备的五元组）

1. **现象**（Phenomenon）：可复现的、可观察到的错误表象。给出可验证的观察结果。
2. **根因**（Root cause）：真正触发问题的原因，指向具体文件/行号/配置/依赖。避免只写「代码有 bug」。
3. **修法**（Fix）：做了什么改变，改到哪个文件/函数/配置。已修复必须能对照到具体 commit。
4. **日期**（Date）：登记的日期，格式 `YYYY-MM-DD`；未修复时用「登记」表示只做了记录。
5. **相关 commit**（Commit）：修复 commit 短 hash；未修复或尚未落盘时写 `—`。

标题后缀：
- **【已修复】**：已合入主干，含修复 commit。
- **【待跟踪】**：已登记但尚未修复。
- **【已作废】**：现象不再出现或原因判定错误，保留以防考古。

## 示例（虚构，仅演示格式）

### P-001: `<一句话标题>` 【待跟踪】
- 现象：`<可观察到的错误输出 / 报错信息 / 行为偏差>`
- 根因：`<path/to/file>:<line-range>` —— `<为什么会出现>`
- 修法：`<做了什么改变>`
- 日期：`YYYY-MM-DD` 登记｜Commit：`—`

### P-002: `<一句话标题>` 【已修复】
- 现象：`<错误表象>`
- 根因：`<文件:行号>` —— `<根因简述>`
- 修法：`<改法简述>`
- 日期：`YYYY-MM-DD`｜Commit：`<7 位 hash>`

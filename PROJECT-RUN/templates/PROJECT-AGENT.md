## 3. 仓库卫生

- 仓库只装源码、文档、脱敏样例、构建脚本；不含运行时产物与真实数据。
- 禁止入库清单：见 §4（本地数据清单）；新增敏感或运行时文件时先判断是否应入库。
- 提交前自查：`git status --short` 必须能逐行解释；出现不认识的未跟踪文件先查来源，再决定加入忽略规则或移除。
- 脱敏样例：任何文档/示例需要真实数据时，只提交 `*.example.*` 或 `*.sample.*` 形式，绝不提交真实值。
- 敏感信息泄露路径排查：commit message、PR 描述、截图、复制的调试输出中不得出现账号标识、cookie 值、内网地址、本地绝对路径。

**忽略规则自查**：`.gitignore` 必须覆盖所有运行时目录，用 `git check-ignore -v <样本路径>` 验证命中。

## 5. Git 与提交纪律

- 禁 `git add -A` / `git add .`，必须显式列出路径。
- 禁 `git stash` / `git reset --hard` / `git checkout .` / `git clean` / `git push --force`（除非人类显式指令）。
- commit message 格式：`type(scope): 描述`；AI 主导的提交末行加 `AI-Model: <模型名>`。
- 提交前跑 pre-commit 检查（若项目启用了钩子：`git config core.hooksPath .githooks`）。
- 若发现文件已被跟踪但应忽略（进了 §4 清单），先 `git rm --cached <路径>` 移除索引，再补忽略规则。
- 禁止 `git commit --no-verify` 绕过检查；勾子失败应先修问题，而非跳过。
